# Digital Heritage Archive & Memorial Kiosk (SIH26096)

An AI-powered digital heritage platform dedicated to Dr. B. R. Ambedkar —
built for Smart India Hackathon (Problem Statement SIH26096), sponsored
by the Ministry of Social Justice and Empowerment, for institutions like
the Dr. Ambedkar International Centre.

This branch (`frontendd`) contains the kiosk frontend. The backend lives
on `main` — see [Backend setup](#backend-setup) below, it must be running
for the AI features to work.

## What it does

- **Manuscript & speech archive** — browse Ambedkar's writings and
  speeches with side-by-side original scan / verbatim transcription,
  multi-language display (English, Marathi, Hindi), and an
  original-vs-AI-restored image comparison slider.
- **AI Research Assistant** — ask questions in the search bar or the
  chat widget; answers are generated by a real backend RAG (Retrieval
  Augmented Generation) pipeline grounded in the archive, with
  volume/page citations. Falls back to a small set of canned answers
  only if the backend is unreachable.
- **Live voice search** — uses the browser's Web Speech API for real
  microphone-based querying (no simulated transcription).
- **Oral history / audio-visual vault** — plays real uploaded audio
  recordings when available (streamed from the backend media library),
  with a simulated demo player as fallback for entries with no file
  uploaded yet.
- **Foreign language translation** — on-demand translation of any
  document into German, Spanish, French, Japanese, Chinese, Russian, or
  Arabic via the backend (covers languages outside BHASHINI's Indian-
  language scope), read aloud via the browser's text-to-speech.
- **Souvenir printing** — generates a real QR code (linking to the
  archive item) from the backend and renders a printable commemorative
  slip.
- **Book/document camera scanner** — uses the device camera to "scan" a
  physical document and jump to the matching digital record. Currently
  matches locally against the demo catalog; wiring this to the
  backend's OCR/cross-modal image search is a natural next step.
- **Interactive timeline** — key chronological events in Ambedkar's life
  and the constitutional process.

## Tech stack

**Frontend:** React 18 + Vite, Tailwind CSS, lucide-react icons,
canvas-confetti, axios. Browser-native Web Speech API (recognition +
synthesis) and camera (`getUserMedia`) — no extra libraries needed for
those.

**Backend** (on `main`): FastAPI, PostgreSQL + PostGIS, Qdrant (vector
search), MinIO (S3-compatible media storage), Redis, Tesseract + TrOCR
(OCR), BAAI/bge-m3 + CLIP (embeddings), Claude (RAG answers &
translation), BHASHINI (Indian-language voice/translation).

## Frontend setup

```bash
npm install
npm run dev
```

Opens at **http://localhost:5173** (Vite's default port).

By default the frontend talks to a backend at `http://localhost:8000`.
To point it elsewhere, create a `.env` file in this folder:

```
VITE_API_BASE_URL=http://your-backend-host:8000
```

## Backend setup

The backend is on the `main` branch, in `heritage-archive/backend/`.
Check it out separately, then:

```bash
cd heritage-archive
docker compose up -d          # Postgres, Qdrant, MinIO, Redis

cd backend
pip install -r requirements.txt

export ANTHROPIC_API_KEY=your_key_here
export DATABASE_URL=postgresql://heritage_admin:change_me_in_env@localhost:5432/heritage_archive

uvicorn main:app --reload --port 8000
```

Optional, for BHASHINI (Indian-language voice) and MinIO media uploads:

```
export BHASHINI_USER_ID=...
export BHASHINI_ULCA_API_KEY=...
export MINIO_ACCESS_KEY=heritage_admin
export MINIO_SECRET_KEY=change_me_in_env
```

The embedding models (bge-m3, CLIP) are large and load lazily on first
use of `/api/v1/search/*` or `/api/v1/rag/chat` — the server itself
starts instantly, and `/api/archives`, `/api/search`, and `/health`
don't need them.

## Running both together

```bash
# terminal 1 — backend
cd heritage-archive/backend && uvicorn main:app --reload --port 8000

# terminal 2 — frontend
npm run dev
```

Open http://localhost:5173. A "LIVE" vs "OFFLINE" indicator on the
search panel shows whether it's actually reaching the backend.
